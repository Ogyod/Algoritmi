# ZIP и API в Algoritmi

Дизайн сайта сохранён. ZIP выбирается прежней кнопкой **Выбрать файлы** или
перетаскивается в прежнюю область загрузки. Затем нажмите **Распознать документы**.
Каждая папка ZIP становится одним документом, фотографии внутри — его страницами.
Файлы в корне обрабатываются отдельно. Используйте имена `1.jpg`, `2.jpg` и так
далее: учитывается числовой порядок, `2.jpg` идёт перед `10.jpg`.

Работают локальный сервер и браузерная сборка сайта. В браузерной сборке архив
распаковывается на устройстве пользователя через существующий Python/WASM worker.
JSON и CSV выгружаются прежними кнопками. Средний балл разных аттестатов не смешивается.

## Лимиты

ZIP до 50 МБ, до 200 файлов PDF/JPEG/PNG/TIFF/WEBP, до 500 записей с учётом папок,
до 200 МБ после распаковки. Каждый файл — до 20 МБ, весь аттестат — до 20 страниц.
Служебные и неподдерживаемые файлы пропускаются. Защищённые паролем архивы, ссылки,
повторяющиеся пути и пути за пределами папки отклоняются. Ошибка одного аттестата
не останавливает остальные.

## Включение API

API доступен у **локального Python-сервера** на `http://127.0.0.1:8765`.
Статическая публикация GitHub Pages обрабатывает документы в браузере и не
предоставляет серверные API-методы.

В PowerShell из папки проекта:

```powershell
$env:APP_API_KEY = & .\.ocr-venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
.\start.ps1
```

Передайте то же значение ключа клиентской программе через её окружение.
Для каждого запроса `/api/v1/` нужен `Authorization: Bearer <ключ>`.
Без ключа API возвращает 503; интерфейс продолжает работать.

| Метод | Адрес | Назначение |
| --- | --- | --- |
| POST | `/api/v1/batches` | Принять ZIP, PDF, изображение или пакет ЛК в JSON |
| GET | `/api/v1/batches/{batch_id}` | Статус и результаты всех документов |
| GET | `/api/v1/documents/{id}` | Результат одного документа |
| POST | `/api/v1/documents/{id}/review` | Сохранить сверенные оценки и расчёт |

## Подключение личного кабинета

ЛК отправляет `POST /api/v1/batches` с `Content-Type: application/json`. Затем
запрашивает `GET` по адресу `results_url` из ответа 202, пока пакет не обработан.
Algoritmi не делает исходящих запросов в ЛК.

Один запрос представляет текущий пакет одного абитуриента. Пример запроса
(`data` нужно заменить содержимым PDF или изображения в Base64):

```json
{
  "applicant_id": "4515",
  "documents": [
    {
      "document_id": "doc-128",
      "type": "auto",
      "complete": true,
      "fields": {"number": "0012345", "series": null, "average_grade": null, "region_code": null},
      "files": [
        {"name": "title.pdf", "role": "certificate", "data": "<BASE64>"},
        {"name": "appendix.pdf", "role": "appendix", "data": "<BASE64>"}
      ]
    }
  ]
}
```

- `applicant_id` и `document_id` принимают строки или целые числа и возвращаются
  строками. Каждый ID документа указывается один раз. Если части аттестата имеют
  разные ID файлов, ЛК группирует их под одним ID аттестата. Формат массива
  `files` сохраняет порядок частей. Файл с ролью `certificate` читается первым,
  `appendix` обозначает отдельное приложение. PDF, содержащий весь аттестат,
  передавайте с ролью `auto`. При отсутствии роли используется `auto`.
- В `fields` передавайте текущие значения. Пустыми считаются отсутствующие ключи,
  `null` и пустые строки. Для серии, номера и кода региона используйте строки,
  чтобы сохранить ведущие нули.
- `type` можно оставить `auto`. Для известного иностранного документа или перевода
  передавайте `foreign`. ЛК также может указать `certificate_9` или `certificate_11`,
  тогда тип сверяется со сканом.
- `complete: true` передаётся, когда ЛК подтвердил наличие аттестата и всех страниц
  приложения. `false` запрещает автоматический расчёт. Если полнота неизвестна,
  передайте `null` либо опустите поле. Тогда для автоматического расчёта нужна
  полная последовательность прочитанных номеров страниц с общим количеством.
  В любом случае нужны титульная часть, границы таблицы и уверенно распознанные
  оценки до заголовка «Дополнительные сведения». Если обнаружено несколько
  титульных листов или в приложении указан другой номер аттестата либо вид
  образования, документ отправляется на сверку. Средний балл округляется
  по существующему правилу до двух знаков после запятой.
- Код региона берётся из явно указанного места выдачи или адреса школы на
  титульной части (например, `"78"` для Санкт-Петербурга). При отсутствии
  однозначных данных поле передаётся на сверку.
- В JSON допускается до 200 файлов в пакете и до 20 файлов на документ.
  До 20 МБ на файл и до 50 МБ исходных данных на пакет до кодирования в Base64.

В ответе GET для каждого документа:

```json
{
  "id": "<внутренний UUID результата>",
  "batch_id": "<UUID пакета>",
  "applicant_id": "4515",
  "document_id": "doc-128",
  "status": "review",
  "change": "unchanged",
  "reused_ocr": true,
  "detected_type": "certificate_11",
  "fields_to_fill": {"series": "АБ", "region_code": "78"},
  "requires_review": true,
  "review": [{"field": "average_grade", "reason": "Не найдены однозначные границы таблицы оценок."}],
  "error": ""
}
```

`change` сравнивает скан с предыдущим пакетом этого абитуриента: `new`,
`unchanged` или `changed`. На уровне пакета `removed_document_ids` перечисляет
ID, которых нет в текущем пакете. Это информационное поле. Каждый POST по-прежнему
создаёт новый ID пакета. Повторный скан может использовать сохранённый OCR, но
`fields_to_fill` каждый раз строится по текущим полям ЛК. Если раньше читались
только реквизиты, запрос среднего балла запускает чтение приложения.

ЛК применяет `fields_to_fill` только к полям, которые остаются пустыми к моменту
записи. Статус `review` может содержать готовые значения для части полей.
Ручную сверку результатов такого запроса выполняет ЛК. Маршрут `/review`,
описанный ниже, предназначен для обычной загрузки ZIP, PDF и изображений.

### Загрузка ZIP, PDF или изображения

```powershell
curl.exe -sS "http://127.0.0.1:8765/api/v1/batches" `
  -H "Authorization: Bearer $env:APP_API_KEY" `
  -F "file=@C:/Documents/attestats.zip"
```

Можно передать файл непосредственно в теле с `Content-Type: application/zip`,
`application/pdf`, `image/png`, `image/jpeg`, `image/tiff` или `image/webp`.
Нужен Content-Length; Transfer-Encoding не поддерживается.

Ответ **202 Accepted** содержит `batch_id`, `results_url`, `total`, `counts`,
`skipped_files` и `documents`. `Location` содержит тот же путь результата.
Повторяйте GET по `results_url` примерно каждые 2 секунды, пока `status`
равен `processing`. Статусы пакета: `processing`, `completed`,
`completed_with_errors`, `failed`, `interrupted`.

```powershell
curl.exe -sS "http://127.0.0.1:8765/api/v1/batches/<batch_id>" `
  -H "Authorization: Bearer $env:APP_API_KEY"
```

У каждого документа есть `id`, `document_key`, `source_files`, `status`,
`revision`, `error`, `requires_review`, `grades`, `pages`, `calculation`, `result`.
В `result` сохранена существующая схема Algoritmi: категория, серия и номер,
текст OCR, оценки, предварительный `average`, замечания и страницы для просмотра.
У страниц есть `source_file` и `source_page` для связи с исходными фотографиями.
`calculation` доступен сразу, когда хотя бы один OCR прочитал каждую найденную оценку
с уверенностью от 80% и нет уверенных противоречий; иначе он появляется после сверки. Это не гарантирует полноту или
безошибочность распознанного списка. Ошибки отдельного документа возвращаются внутри
успешного GET с HTTP 200.

### Сверка

POST `/api/v1/documents/{id}/review`, `Content-Type: application/json`:

```json
{
  "revision": 2,
  "complete": true,
  "type": "certificate_9",
  "document_series": "АБ",
  "document_number": "0012345",
  "grades": [
    {"subject": "Математика", "grade": 5, "verified": true},
    {"subject": "Физика", "grade": 4, "verified": true}
  ]
}
```

Передайте текущую ревизию и полный список предметов. `complete: false` сохраняет
черновик, `complete: true` подтверждает сверку и возвращает статус `ready`.
Для аттестата проверяются оценки от 2 до 5, отсутствие повторов и подтверждение
`verified: true`. Серия и номер берутся из OCR либо переданных исправлений. Если OCR
не нашёл реквизиты, оставьте соответствующие поля пустыми: это не препятствует
подтверждению. Если на документе действительно нет серии, можно дополнительно
передать `series_not_present: true`.
Проверенный расчёт будет `{"sum":9,"count":2,"value":"4.50"}`.
Устаревшая ревизия отклоняется. API не меняет профили абитуриентов.

## Хранение и ошибки

Результаты API сохраняются в `data/batches.sqlite3` и доступны после перезапуска.
Входные файлы временно хранятся в `data/<UUID>-input` и удаляются после успешной
обработки. При ошибке входные файлы ЛК удаляются, а файлы обычной загрузки
остаются для диагностики. ZIP целиком не сохраняется.
Незавершённая обработка восстанавливается при следующем запуске.
Повторный POST создаёт новый пакет; для чтения ранее принятого пакета сохраняйте
его идентификатор. Состояние интерфейса, как и раньше, хранится в открытой вкладке.

Ошибки возвращаются как JSON `{"error":"Описание"}`. Основные коды: 400 —
некорректные данные, 401 — неверный ключ, 404 — нет документа/пакета, 411 —
нужен Content-Length, 413 — слишком большой запрос, 415 — неподдерживаемый
Content-Type, 503 — API не включён. Старые методы `/api/process` и
`/api/reinterpret` сохранены; добавлены внутренние `/api/archive` и
`/api/process-group` для существующего интерфейса.
