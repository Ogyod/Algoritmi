# ZIP и API в Algoritmi

Дизайн сайта сохранён. ZIP выбирается прежней кнопкой **Выбрать файлы** или
перетаскивается в прежнюю область загрузки. Затем нажмите **Распознать документы**.
Каждая папка ZIP становится одним документом, фотографии внутри — его страницами.
Файлы в корне обрабатываются отдельно. Используйте имена `1.jpg`, `2.jpg` и так
далее: учитывается числовой порядок, `2.jpg` идёт перед `10.jpg`.

Работают локальный сервер и браузерная сборка сайта. В браузерной сборке архив
распаковывается на устройстве пользователя через существующий Python/WASM worker.
JSON и CSV выгружаются прежними кнопками. Средний балл разных аттестатов не смешивается.

## Лимиты

ZIP до 50 МБ, до 200 файлов PDF/JPEG/PNG/TIFF/WEBP, до 500 записей с учётом папок,
до 200 МБ после распаковки. Каждый файл — до 20 МБ, весь аттестат — до 20 страниц.
Служебные и неподдерживаемые файлы пропускаются. Защищённые паролем архивы, ссылки,
повторяющиеся пути и пути за пределами папки отклоняются. Ошибка одного аттестата
не останавливает остальные.

## Включение API

API доступен у **локального Python-сервера** на `http://127.0.0.1:8765`.
Статическая публикация GitHub Pages обрабатывает документы в браузере и не
предоставляет серверные API-методы.

В PowerShell из папки проекта:

```powershell
$env:APP_API_KEY = .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
.\.venv\Scripts\python.exe -X utf8 server.py --open
```

Передайте то же значение ключа клиентской программе через её окружение.
Для каждого запроса `/api/v1/` нужен `Authorization: Bearer <ключ>`.
Без ключа API возвращает 503; интерфейс продолжает работать.

| Метод | Адрес | Назначение |
| --- | --- | --- |
| POST | `/api/v1/batches` | Принять ZIP, PDF или изображение |
| GET | `/api/v1/batches/{batch_id}` | Статус и результаты всех документов |
| GET | `/api/v1/documents/{id}` | Результат одного документа |
| POST | `/api/v1/documents/{id}/review` | Сохранить сверенные оценки и расчёт |

### Загрузка

```powershell
curl.exe -sS "http://127.0.0.1:8765/api/v1/batches" `
  -H "Authorization: Bearer $env:APP_API_KEY" `
  -F "file=@C:/Documents/attestats.zip"
```

Можно передать файл непосредственно в теле с `Content-Type: application/zip`,
`application/pdf`, `image/png`, `image/jpeg`, `image/tiff` или `image/webp`.
Нужен Content-Length; Transfer-Encoding не поддерживается.

Ответ **202 Accepted** содержит `batch_id`, `results_url`, `total`, `counts`,
`skipped_files` и `documents`. `Location` содержит тот же путь результата.
Повторяйте GET по `results_url` примерно каждые 2 секунды, пока `status`
равен `processing`. Статусы пакета: `processing`, `completed`,
`completed_with_errors`, `failed`, `interrupted`.

```powershell
curl.exe -sS "http://127.0.0.1:8765/api/v1/batches/<batch_id>" `
  -H "Authorization: Bearer $env:APP_API_KEY"
```

У каждого документа есть `id`, `document_key`, `source_files`, `status`,
`revision`, `error`, `requires_review`, `grades`, `pages`, `calculation`, `result`.
В `result` сохранена существующая схема Algoritmi: категория, серия и номер,
текст OCR, оценки, предварительный `average`, замечания и страницы для просмотра.
У страниц есть `source_file` и `source_page` для связи с исходными фотографиями.
До сверки `calculation` равен null; предварительный средний не означает проверку
точности или полноты OCR. Ошибки отдельного документа возвращаются внутри
успешного GET с HTTP 200.

### Сверка

POST `/api/v1/documents/{id}/review`, `Content-Type: application/json`:

```json
{
  "revision": 2,
  "complete": true,
  "type": "certificate_9",
  "document_series": "АБ",
  "document_number": "0012345",
  "grades": [
    {"subject": "Математика", "grade": 5, "verified": true},
    {"subject": "Физика", "grade": 4, "verified": true}
  ]
}
```

Передайте текущую ревизию и полный список предметов. `complete: false` сохраняет
черновик, `complete: true` подтверждает сверку и возвращает статус `ready`.
Для аттестата проверяются оценки от 2 до 5, отсутствие повторов и подтверждение
`verified: true`. Серия и номер берутся из OCR либо переданных исправлений;
если серии нет, передайте пустую серию и `series_not_present: true`.
Проверенный расчёт будет `{"sum":9,"count":2,"value":"4.50"}`.
Устаревшая ревизия отклоняется. API не меняет профили абитуриентов.

## Хранение и ошибки

Результаты API сохраняются в `data/batches.sqlite3` и доступны после перезапуска.
Входные файлы временно хранятся в `data/<UUID>-input` и удаляются после успешной
обработки; при ошибке остаются для диагностики. ZIP целиком не сохраняется.
Незавершённая обработка восстанавливается при следующем запуске.
Повторный POST создаёт новый пакет; для чтения ранее принятого пакета сохраняйте
его идентификатор. Состояние интерфейса, как и раньше, хранится в открытой вкладке.

Ошибки возвращаются как JSON `{"error":"Описание"}`. Основные коды: 400 —
некорректные данные, 401 — неверный ключ, 404 — нет документа/пакета, 411 —
нужен Content-Length, 413 — слишком большой запрос, 415 — неподдерживаемый
Content-Type, 503 — API не включён. Старые методы `/api/process` и
`/api/reinterpret` сохранены; добавлены внутренние `/api/archive` и
`/api/process-group` для существующего интерфейса.
